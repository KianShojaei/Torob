# دستیار هوشمند خرید حضوری ترب در تهران (Torob In-Store Shopping Assistant)

این پروژه راهکار جامع، هوشمند و ایجنتیک (Agentic AI) برای **مسابقه هکاتون ترب** است که با هدف حل چالش‌های واقعی **خرید حضوری از فروشگاه‌های کوچک و بزرگ، پاساژها و مراکز خرید تهران** طراحی و پیاده‌سازی شده است.

---

## ۱. مسئله‌ای که حل می‌کنیم و پوشش چهار گام اصلی دستیار

در خرید حضوری از بازارها و پاساژهای تهران (مانند پاساژ علاءالدین، چارسو، بازار موبایل، پایتخت، لاله‌زار و...)، خریدار با عدم قطعیت در انتخاب مدل، قدیمی بودن قیمت‌های ثبت‌شده، دشواری پیدا کردن واحد دقیق در پاساژ و ابهام در شرایط اقساطی یا ساعت کاری مواجه است. این دستیار چهار گام اصلی زیر را به صورت یکپارچه پوشش می‌دهد:

1. **گام اول — تصمیم‌گیری و انتخاب مدل مناسب (Decide What to Buy):**
   * درک نیاز کاربر به زبان طبیعی فارسی (حتی با وجود غلط‌های املایی رایج مانند «شیاومی» به‌جای «شیائومی» یا توصیف ویژگی مثل «موبایلی که باتریش خوب باشه»).
   * تفکیک هوشمند **«کالای اصلی (Target Entity)»** از **«ویژگی/قطعه جانبی»** (مثلاً وقتی کاربر موبایل با باتری قوی می‌خواهد، گوشی‌های دارای باتری ۵۰۰۰ میلی‌آمپر به بالا پیشنهاد می‌شوند، نه باتری یدکی!).
   * ارائه مدل‌های پیشنهادی به همراه **قیمت منصفانه بازار (Fair Market Price)**، دلایل پیشنهاد و **جدول مقایسه مشخصات فنی کنار هم**.
   * تنظیم خودکار فیلترهای بودجه، برند، شرایط پرداخت قسطی، وسیله نقلیه و نوع مرتب‌سازی مستقیماً از روی متن نوشته شده توسط کاربر + امکان انتخاب دستی در پنجره مجزای «انتخاب اولویت و برند».
   * **جایگزین‌یابی صادقانه در سطح کاتالوگ:** اگر برند یا مدل خاصی در بازه بودجه کاربر در دیتاست موجود نباشد، دستیار به صورت شفاف عدم موجودی آن برند را اعلام کرده و بهترین جایگزین‌های هم‌رده موجود در بازار تهران را پیشنهاد می‌دهد.

2. **گام دوم — یافتن فروشگاه‌های حضوری در تهران و نمای نقشه زنده (Find Nearby Stores & Live Map):**
   * انتخاب سلسله‌مراتبی موقعیت مکانی: **انتخاب شهر (تهران) ← انتخاب «همه مناطق تهران» یا یکی از ۳۰ محله دیتاست (فردوسی، شیخ هادی، بهارستان، جمهوری، ولیعصر و...) یا مکان‌یابی زنده با GPS**.
   * نمایش همزمان فروشگاه‌ها روی **نقشه تعاملی (OpenStreetMap / Leaflet)** با درج مستقیم برچسب قیمت روی پین‌های نقشه (به سبک GPT Maps) و جلوگیری از روی هم افتادن پین‌های یک پاساژ (Spiral Coordinate Offset).
   * تفکیک سخت‌گیرانه فروشگاه‌های دارای آفر واقعی در `offers.csv` از فروشگاه‌هایی که صرفاً دسته‌بندی فعالیت مرتبط دارند.

3. **گام سوم — مقایسه شفاف فروشگاه‌ها (Compare Stores):**
   * امتیازدهی ترکیبی شفاف در بازه `[0, 1]` بر اساس: **قیمت نسبت به کف بازار (۳۰٪)، مسافت و زمان رسیدن با خودرو/مترو/پیاده (۲۵٪)، باز بودن در لحظه رسیدن کاربر (۲۰٪)، تازگی و تأیید قیمت (۱۵٪) و شرایط خرید قسطی/گارانتی (۱۰٪)**.
   * ارائه **جدول مقایسه ستون‌به‌ستون فروشگاه‌ها** (قیمت، ارزیابی منصفانه بودن قیمت، فاصله، ساعت کاری در زمان رسیدن، شرایط اقساط و آدرس داخل پاساژ).

4. **گام چهارم — استعلام زنده از فروشنده، چانه‌زنی هوشمند قیمت و جایگزین‌یابی خودکار (Contact, Negotiate & Failover):**
   * ارتباط همزمان یا تکی با فروشگاه‌ها برای استعلام موجودی، قیمت روز، ساعت کاری و شماره واحد داخل پاساژ.
   * **موتور پیشنهاد قیمت منصفانه (Smart Fair-Price Counter-Offer):** محاسبه قیمت متعادل بازار و ارسال پیشنهاد قیمت به فروشنده برای دریافت تخفیف خرید حضوری.
   * **جایگزین‌یابی خودکار (Automatic Failover):** در صورتی که فروشنده اعلام **عدم موجودی (Out of Stock)** کند یا در زمان مقرر **پاسخ ندهد (Timeout)**، سامانه به صورت خودکار فروشگاه‌های جایگزین دارنده همان کالا و همچنین مدل‌های مشابه را پیشنهاد می‌دهد.
   * **تکمیل پایپ‌لاین مراجعه حضوری:** پس از تأیید موجودی و قیمت توسط فروشنده، کاربر با یک کلیک فروشگاه را به **«برنامه مسیر مراجعه حضوری»** اضافه کرده و ترتیب بهینه مراجعه، ساعت رسیدن و لینک مستقیم مسیریابی در **نشان، بلد و گوگل‌مپ** را دریافت می‌کند.

## ۲. رعایت اصول شفافیت داده‌ها و قوانین دیتاست ترب (۲۰ امتیاز دیتاست)

تمامی قواعد تمیزکاری و شفافیت داده‌ها روی دیتاست رسمی چالش اعمال و با تست‌های خودکار راست‌آزمایی شده‌اند:

| شاخص دیتاست | مقدار استخراج‌شده در پایپ‌لاین ETL | توضیح فنی نحوه پردازش |
| :--- | :---: | :--- |
| **تعداد کل فروشگاه‌های تهران (`shops.csv`)** | `6,476` | استخراج ۳۰ محله تهران و محاسبه مرکز ثقل جغرافیایی (Centroid) هر محله |
| **فروشگاه‌های دارای نام واقعی** | `112` | شامل `22` فروشگاه دارای اینستاگرام و `90` فروشگاه دارای وب‌سایت |
| **فروشگاه‌های دارای سرویس خرید قسطی** | `266` | تفکیک دو سطحی: `82` فروشگاه **«قسطی حضوری تأییدشده (`in_person`)»** و سایرین **«قسطی اعلام‌شده (`unknown`)»** (ترب‌پی، اسنپ‌پی، دیجی‌پی، تارا، ازکی‌وام) |
| **فروشگاه‌های دارای برنامه ساعت کاری** | `4,473` | پردازش `27,270` روز کاری اعلام‌شده، `4,006` روز تعطیل و `35` روز نامشخص؛ پشتیبانی از دو شیفت کاری و شیفت‌های عبوری از نیمه‌شب (Cross-Midnight) |
| **فروشگاه‌های واقع در پاساژ/مجتمع تجاری** | `4,840` | استخراج نام پاساژ، طبقه و واحد با Regex و یکسان‌سازی املاهای مختلف (مانند علاءالدین / علاالدین / علالدین) |
| **تعداد کل محصولات یکتا (`products.csv`)** | `225,903` | نرمال‌سازی فارسی/عربی/انگلیسی، استخراج برند، مشخصات کلیدی (`compact_specs`) و خوشه‌بندی مدل‌های مشابه (`product_group_id`) |
| **تعداد کل آفرها (`offers.csv`)** | `331,506` | حذف `20,315` آفر تکراری بر اساس جدیدترین تاریخ تغییر قیمت (`311,191` آفر یکتا) و اصلاح هوشمند قیمت‌های ثبت‌شده به ریال (۱۰ برابر تومان) |

### قانون طلایی تفکیک سه‌گانه قیمت و موجودی:
در تمامی کارت‌ها و جداول سامانه، هرگز قیمت ثبت‌شده با موجودی تأییدشده ادغام نمی‌شود و همیشه ۳ بخش مستقل نمایش داده می‌شود:
1. **قیمت ثبت‌شده / قیمت تأییدشده** (مقادیر نامعتبر، صفر یا پرت به عنوان `قیمت نامشخص` نمایش داده می‌شوند).
2. **زمان آخرین تغییر قیمت** (محاسبه‌شده نسبت به تاریخ اسنپ‌شات دیتاست `2026-10-13`).
3. **وضعیت موجودی** (`ثبت‌شده در لیست فروشگاه (تأیید نشده)` در برابر `تأییدشده توسط فروشنده` یا `ناموجود`).

## ۳. معماری فنی و ساختار پروژه

```text
├── backend/
│   ├── app/
│   │   ├── agent/
│   │   │   └── orchestrator.py       # مغز ایجنت، استخراج هوشمند فیلترها از متن طبیعی و اتصال به LLM (BoxAPI/OpenAI)
│   │   ├── db/
│   │   │   ├── bootstrap.py          # بازگشایی خودکار دیتابیس فشرده در زمان بالا آمدن سرور/داکر
│   │   │   └── repo.py               # موتور جستجوی هیبریدی، نرمال‌ساز قیمت ریال/تومان و تطبیق موجودیت/ویژگی
│   │   ├── etl/
│   │   │   ├── address_parser.py     # پارسر آدرس، استخراج نام پاساژ/طبقه/واحد و ساخت راهنمای گام‌به‌گام پاساژ
│   │   │   ├── build_db.py           # پایپ‌لاین کامل تبدیل CSVهای خام به دیتابیس SQLite و گزارش اعتبارسنجی
│   │   │   ├── hours_engine.py       # موتور محاسبه ساعت کاری (به وقت تهران) و بررسی باز بودن در لحظه رسیدن
│   │   │   ├── installment_parser.py # پارسر دو سطحی سرویس‌های خرید اعتباری و قسطی
│   │   │   ├── normalizer.py         # نرمال‌ساز حروف و اعداد فارسی و اصلاح فونتیک غلط‌های املایی
│   │   │   ├── price_rules.py        # اعتبارسنجی قیمت و دسته‌بندی سن قیمت (Fresh / Recent / Old / Stale)
│   │   │   └── product_enrichment.py # استخراج مشخصات فنی فشرده و گروه‌بندی محصولات مشابه
│   │   ├── services/
│   │   │   └── ranking.py            # موتور رتبه‌بندی شفاف فروشگاه‌ها، راهنمای پاساژ و برنامه‌ریز مسیر مراجعه (TSP)
│   │   ├── simulator/
│   │   │   └── seller_sim.py         # شبیه‌ساز قطعی (Deterministic) فروشندگان، چانه‌زنی قیمت و Failover خودکار
│   │   ├── config.py                 # تنظیمات محیطی برنامه
│   │   └── main.py                   # اندپوینت‌های REST، استریم SSE و سروینگ یکپارچه فرانت‌اند
│   ├── tests/                        # تست‌های واحد (Unit Tests) و یکپارچه‌سازی (Integration Tests)
│   └── requirements.txt              # وابستگی‌های پایتون
├── frontend/
│   └── index.html                    # رابط کاربری فارسی (RTL، Mobile-First)، نقشه زنده، فونت وزیرمتن و طراحی انسانی
├── data/
│   └── torob_portable.db.gz          # بسته فشرده دیتابیس پردازش‌شده برای راه‌اندازی آنی روی سرور و لیارا
├── docs/
│   ├── DEMO_SCRIPT.md                # سناریوی دقیقه به دقیقه ویدئوی دمو (۵ دقیقه)
│   └── JUDGING_CHEAT_SHEET.md        # راهنمای سریع ارزیابی داوران بر اساس بارم‌بندی ۳۰۰ امتیازی
├── Dockerfile                        # فایل ساخت ایمیج داکر آماده پروداکشن
├── docker-compose.yml                # راه‌اندازی تک‌دستوری روی سرورهای لینوکسی
└── liara.json                        # تنظیمات دیپلوی خودکار و Healthcheck روی زیرساخت لیارا (Liara)
```

## ۴. راهنمای نصب و اجرا (لوکال، داکر و لیارا)

### الف) اجرای سریع روی سیستم لوکال (بدون داکر)

```bash
# ۱. نصب پکیج‌ها
pip install -r backend/requirements.txt

# ۲. کپی فایل تنظیمات محیطی و قرار دادن کلید API
cp .env.example .env

# ۳. اجرای سرور (در اولین اجرا، دیتابیس فشرده به صورت خودکار در ۲ ثانیه باز می‌شود)
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

سپس مرورگر را در آدرس `http://localhost:8000` باز کنید.

### ب) اجرای تست‌های خودکار
```bash
pytest
```

### ج) اجرا با Docker و Docker Compose روی هر سرور (VPS)
```bash
cp .env.example .env
docker compose up -d --build
```

### د) دیپلوی روی زیرساخت ابری لیارا (Liara)
```bash
npm install -g @liara/cli
liara login
liara deploy --port 8000
```
